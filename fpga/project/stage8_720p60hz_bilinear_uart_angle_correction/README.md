# Stage 8 720p60Hz 双线性插值 UART 角度校正工程

本工程由 `stage8_brown_y_uart_parameter_test` 复制，集中保留当前已实板验证的功能：720p（1280×720）视频链路、双线性插值、UART 参数接收，以及通过单应矩阵实现的角度校正。参数在输出帧边界原子更新；UART 协议上传的是 3×3 单应矩阵，不是角度数值本身，上位机需先将目标角度换算为矩阵系数。

## 串口接口

- 板卡：盘古 200Pro+（PG2L200H-6-FBB676）
- USB-UART：115200 baud、8-N-1、无流控
- FPGA RX：B24；FPGA TX：C24
- 板载 LED3（FPGA 引脚 E18）：每接收完一帧请求翻转一次，包括接受和拒绝的请求
- HDMI 仍保持原视频链路；参数只在下一个接受的输出帧开始处原子生效

## 参数帧

请求和响应均为 45 字节。串口工具使用十六进制发送，关闭自动重发，并一次只发送一帧，收到完整响应后再发送下一帧。

| 偏移 | 长度 | 请求 | 响应 |
|---:|---:|---|---|
| 0 | 2 | `A5 5A` | `A5 5A` |
| 2 | 1 | 协议版本 `01` | `01` |
| 3 | 1 | 请求类型 `01` | 响应类型 `81` |
| 4 | 2 | 小端序号，同时作为参数版本 | 回显序号 |
| 6 | 1 | flags：bit 0 为 pose_valid，bit 7:1 必须为 0 | 状态码，`00` 表示接受 |
| 7 | 36 | 9 个 row-major 的小端 32 位单应系数 | 回显系数 |
| 43 | 2 | CRC 高字节在前 | CRC 高字节在前 |

系数顺序为 `h00,h01,h02,h10,h11,h12,h20,h21,h22`。前两行是有符号 Q16.16，末行是有符号 Q2.30；`h22` 必须为 `0x40000000`。CRC 为 CRC-16/CCITT-FALSE（poly `0x1021`、init `0xFFFF`、无反射、xorout `0`），覆盖偏移 2 至 42。解析器还检查协议字段、标志和 1280×720 四角坐标范围。无效、残缺、CRC 错误或超范围数据不更新参数。

接受的数据先进入 pending 参数组；视频处理引擎在下一帧边界将它切换为 active 参数。映射器把输出坐标映射到源图坐标，因此 `h02=+16 px` 会让输出从输入图像右侧多取 16 像素，画面内容相对左移。首个合法角度包可用该平移确认参数确实经过 UART、参数 bank 和坐标映射链路。

## 生成测试帧

默认生成单位矩阵请求：

```powershell
.\sim\Build-UartPacket.ps1
```

生成 16 像素源坐标平移请求（序号 2）：

```powershell
.\sim\Build-UartPacket.ps1 -Sequence 2 -PoseValid $true -Words `
  00010000 00000000 00100000 `
  00000000 00010000 00000000 `
  00000000 00000000 40000000
```

将输出的 45 个字节粘贴到串口助手的 Hex 发送框。合法帧应返回头部 `A5 5A 01 81`、相同序号、状态 `00` 和系数回显。再发不同平移量可观察更新；不合法 CRC 应返回状态 `04`，并保持原参数不变。

## 仿真和构建

```powershell
.\sim\Run-UartHomographyControl.ps1
.\sim\Build-UartPacket.ps1
.\Build-UartParameterTest.ps1
```

UART 仿真直接按 8-N-1 发送完整参数帧并接收 FPGA 响应，检查 ACK/NACK、CRC、序号、系数回显，以及活动矩阵只在模拟帧边界更新。PDS 构建生成匹配的 `.sbit/.fic`；烧录后用本工程配套 FIC。构建通过和 RTL 仿真通过不等同于完成实板视频效果验证，仍需烧录本工程后从 HDMI 观察单位矩阵与平移矩阵的差异。

## 流水线与时序

单应映射器为 17 级弹性流水线，复位后的有效像素延迟为 17 个时钟周期；流水线灌满后仍可每周期接收一个像素，并在下游阻塞时连同坐标、像素和帧元数据一起停顿。本版本把投影系数乘加、倒数估算与修正、以及 44×33 位坐标乘法拆到多级寄存器间，避免单拍承载整段宽位运算。

2026-10-27 的完整 PDS 布局布线报告为 `Design Summary : All Constraints Met`。最紧的 setup 裕量为 `0.014 ns`（`ddrphy_sysclk`，最差路径落在现有角度/Brown 映射数据通路）；UART 控制路径没有成为 setup 最差路径。该裕量很小，后续改动仍需重新跑完整布局布线确认。
