# 基于 FPGA 几何校正与轻量 AI 的工业安全感知终端：落地思路

> 文档定位：这是项目从“镜头畸变矫正”升级为可参赛、可展示、可继续产品化的工业应用方案。本文讲清楚为什么做、做成什么、如何逐阶段从当前工程生长出来；不作为具体 RTL 文件、代码接口或逐项开发任务清单。

## 1. 项目重新定位

当前工程已经不只是一个畸变公式：它具备 HDMI 视频输入输出、DDR3 完整帧缓存、反向坐标映射、Tile Cache、双线性插值、输入/输出 Ping-Pong 和帧级调度等基础。

这些能力适合被定位为一个 **宽视场工业视觉前端**。畸变矫正不再是最终目的，而是后续空间感知可信的前提。

建议最终题目表述为：

> **基于 FPGA 几何校正与轻量 AI 的宽视场工业作业区安全感知与分级预警终端**

它面对的问题是：在仓储、工厂装卸区等人车混行环境中，普通单目广角画面边缘变形明显，画面中的像素距离不能直接代表现实中的安全距离。仅靠目标检测知道“画面里有一个人、一辆叉车”，仍不足以判断人员是否进入禁入区、是否接近车辆盲区，以及风险等级是否需要升级。

本项目要回答的是：

```text
画面里有什么？                 → 轻量 AI 目标检测
目标处在作业区的什么位置？     → FPGA 几何校正与地面坐标映射
它是否构成安全风险？           → FPGA 围栏、距离和风险状态判断
如何让现场人员立即看见并响应？ → HDMI 可视化、声光与事件上报
```

## 2. 推荐落地场景：仓储叉车与人员混行安全

首选将作品落在一个可在实验室复现的缩小版仓储/装卸区：地面划出绿色安全区、黄色缓冲区、红色叉车禁入区，用小车模拟叉车，用人员或人形标靶模拟作业人员。

选择这一场景的原因是：

- 120° 广角可以覆盖一个完整作业角落，不必使用 180° 超鱼眼；
- 人和叉车两类目标足以构成有说服力的风险关系，不需要堆叠很多 AI 类别；
- 禁入、越界、靠近、滞留等事件容易被评委直观看到；
- “广角失真会使边缘位置判断不可靠”这一痛点，能够自然说明 FPGA 去畸变的必要性；
- 该方案可从桌面微缩演示扩展到真实厂房/仓库，而不改变核心技术路线。

演示中应避免宣称“替代工业级安全系统”或“可直接控制车辆”。更准确的定位是：**面向人车混行作业区的视觉辅助预警终端原型**。

## 3. 从当前工程自然生长出的整体架构

首阶段使用 120° USB-UVC 广角相机，电脑承担协议桥接角色，不让 USB/UVC 问题吞掉 FPGA 项目时间：

```text
120° USB 广角相机
        ↓
电脑：UVC 采集并原样 HDMI 输出
        ↓
FPGA：HDMI 输入 → DDR 帧缓存 → 几何校正 → 安全判断 → HDMI 输出
        ↓
显示器：校正画面、电子围栏、目标与风险等级
        ↓
LED / 蜂鸣器 / 串口或网络事件上报
```

电脑在这一阶段不负责去畸变、几何判断或风险告警，只解决 USB 摄像头怎样稳定进入现有 HDMI FPGA 视频链的问题。这样可以最大程度复用当前工程，也可以在答辩中清楚说明 FPGA 的核心价值。

后续若换用带 HDMI 输出的相机，或改用 DVP/MIPI 摄像头模组，电脑桥接可被替换，但 FPGA 内部主链不需要推倒重来。

## 4. 为什么选择 120°，而不是 150°–210° 鱼眼

120° 是覆盖范围、目标分辨率、标定难度与工程风险之间较好的折中。

当前工程采用的是 Brown–Conrady 风格的径向/切向畸变模型。对普通广角和中等畸变的 120° 镜头，它通常有机会通过真实标定得到可用结果；而 150°–210° 超广角或圆形鱼眼往往更接近等距、等立体角或 Kannala–Brandt 一类的鱼眼投影模型，直接套用现有模型，边缘误差可能难以接受。

因此项目的原则不是“买到 120° 就一定匹配”，而是：

1. 购买保留原始广角畸变、未被相机内部数字校正的 120° 镜头；
2. 用最终进入 FPGA 的画面做棋盘格标定；
3. 先验证当前数学模型的边缘误差；
4. 若模型不够准，则把坐标产生部分升级为标定网格 LUT，而保留后端的 DDR、Tile Cache 和双线性插值结构。

这条“模型标定优先、网格 LUT 兜底”的路线本身就是工程亮点：系统不绑定某一个镜头公式，而是能适配真实镜头。

## 5. FPGA 在系统中的独特价值

项目不应被描述为“电脑识别后显示在 FPGA 上”，而应突出 FPGA 完成确定性、带宽密集且对时序敏感的部分：

```text
完整帧随机访问与重采样
→ 宽视场几何校正
→ 校正坐标系下的区域映射
→ 虚拟电子围栏和风险状态机
→ 连续视频输出与低抖动告警
```

当前工程的 Tile Cache、DDR Burst、Ping-Pong 帧缓存和调度器解决的，正是“畸变校正需要随机读取完整源帧，不能做简单逐像素直通”的问题。它们可以被答辩为系统实现难点，而不是隐藏在背景里的代码细节。

最终可以用一句话概括 FPGA 的作用：

> AI 负责识别目标语义；FPGA 负责把广角视频变成可用于空间判断的稳定几何信息，并实时输出可执行的风险结果。

## 6. 轻量 AI 的合理位置

AI 的目标保持克制：只做 `person` 与 `forklift/vehicle` 两类检测，输出目标框、类别和置信度。目标框的底部中心可近似理解为目标与地面的接触点，再由 FPGA 映射到校正后的地面坐标和电子围栏坐标系。

轻量 AI 的部署路线分两层：

### 第一层：混合式演示与算法验证

电脑可以在采集同一相机流的同时运行 INT8 检测模型，并把目标类别和坐标作为元数据发送给 FPGA。FPGA 仍负责空间映射、风险等级、可视化和告警。

这能快速验证“目标检测 + 几何安全判断”的完整产品逻辑，但必须诚实标注为：**PC 侧 AI 推理 + FPGA 侧几何与风险决策**。

### 第二层：盘古 200 升级方向

未来换用资源更充足的盘古 200 后，可将同一个 INT8 模型迁移到 FPGA 加速器、板载处理器或与板卡协同的计算单元。迁移时应尽量保持“目标框/类别/置信度 → 空间映射 → 风险判定”的模块边界不变。

这样，轻量 AI 是可替换的目标感知模块，不会和现有视频校正系统深度耦合；先做电脑侧验证不会浪费后续工作。

## 7. 分阶段升级路线

### 阶段 A：先把现有视频校正主链变成可靠底座

第一目标不是增加新功能，而是确认现有 HDMI、DDR、连续帧调度、输出帧切换和时序能够稳定运行。零畸变参数只用于确认画面连通与帧缓存可靠，不能当作实际去畸变成果。

这个阶段完成后，系统要能稳定地把电脑 HDMI 输入持续送到 HDMI 输出。

### 阶段 B：接入真实 120° 相机并建立真实标定

在“相机 → 电脑 → HDMI → FPGA”的最终信号路径上采集棋盘格。通过标定得到内参、畸变参数、重投影误差与边缘效果，替代当前仅用于调通链路的默认参数。

展示重点是原始广角画面与 FPGA 矫正画面的对比：直线、边缘格点和场地区域边界应更符合实际几何。

### 阶段 C：从画面校正升级为电子围栏

在校正画面上定义绿色、黄色、红色区域，将画面坐标映射到演示场地平面坐标。此时即使不接 AI，也可以使用移动标靶或人工输入目标位置展示：

```text
进入黄色区域 → 预警
进入红色禁入区 → 红色告警 + 声光提示
离开禁区并持续稳定 → 解除告警
```

这一阶段让项目第一次真正回答“为什么要去畸变”，因为围栏和距离判断开始依赖校正后的几何关系。

### 阶段 D：加入轻量 AI 人车检测

接入两类目标后，系统不仅知道“某个点越界”，还知道是人员还是叉车。展示的风险逻辑可逐步增加：

- 人员进入机械/叉车禁入区；
- 叉车进入人员缓冲区；
- 人车距离持续缩短；
- 目标在危险区滞留超过设定时间。

开始时不追求全功能。先确保人车两类检测、目标位置、围栏和告警在同一画面中逻辑一致，再扩展轨迹和碰撞时间预测。

### 阶段 E：端侧 AI 与产品化增强

换用盘古 200 后，目标是减少电脑侧推理依赖，并增加更高分辨率、多路输入、目标跟踪、事件录像、网络上报和设备健康诊断等能力。

无论是否完成该阶段，比赛初版都应保证前四个阶段能独立闭环，不能把“未来换板”作为当前演示无法运行的理由。

## 8. 比赛演示如何讲清楚必要性

推荐把展示设计成一个逐层递进的 90 秒闭环：

1. **原始问题**：显示 120° 广角下的作业区，边缘直线弯曲、目标位置难直接比较；
2. **几何校正**：切换到 FPGA 矫正输出，展示棋盘格/地面边界恢复；
3. **区域理解**：叠加绿色安全区、黄色缓冲区和红色禁入区；
4. **风险事件**：人员或标靶从安全区进入红区，屏幕显示风险等级，LED/蜂鸣器同步响应；
5. **AI 升级**：出现人员与叉车时，显示类别和置信度，说明 AI 负责语义识别、FPGA 负责可信空间判断。

评委真正能看到的不是“一个图像变直了”，而是：

> 同一台广角相机，在没有额外激光雷达或多摄像头的条件下，经过 FPGA 几何处理和轻量 AI 目标感知，形成了人车混行区域的可视化安全预警闭环。

## 9. 关键风险与边界

| 风险 | 应对原则 |
| --- | --- |
| 120° 镜头仍不能被当前模型准确拟合 | 用真实标定误差决定；必要时升级为网格 LUT，不硬凑参数。 |
| USB UVC 增加 FPGA 接口难度 | 电脑仅做 UVC→HDMI 桥接，维持 FPGA HDMI 主链不变。 |
| 电脑输出模式与 FPGA 不匹配 | 首先锁定分辨率、帧率、RGB 色彩格式和无缩放传递，再谈算法。 |
| AI 演示看起来依赖电脑 | 明确标注混合架构；把 FPGA 的几何校正、围栏、告警作为独立可运行能力。 |
| 目标检测不稳定 | 首版限制为人/叉车两类，先把数据、模型和场景固定，避免泛化承诺。 |
| 项目同时改视频、标定、AI 和硬件而失控 | 始终按“视频稳定 → 真实标定 → 围栏闭环 → AI 升级”的顺序推进。 |

## 10. 近期决策与下一步

近期只需要确定三件事：

1. 购买/借用同系列 120° 广角 UVC 相机，并确认没有机内去畸变；
2. 让电脑稳定输出与 FPGA 输入匹配的 720p30 HDMI 信号；
3. 优先完成真实标定与校正效果验证，而不是立刻接入检测模型。

只要这三步成立，当前项目就可以从“FPGA 畸变校正系统”清晰地升级为“面向工业安全的宽视场视觉前端”。后续的电子围栏和轻量 AI 都是在这块可靠底座上的自然扩展。
