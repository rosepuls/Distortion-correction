## 经过与结论

1. 阶段 1 的 HDMI 直通已在板上确认。电脑的桌面模式和**活动信号模式**都必须是 1280×720@60 Hz；MS7200 EDID 已限制为 720p60。
2. 厂商 `4_10_timing` 工程改成 720p60 后，RGB565 DDR3 缓存版画面大部分正常，但每约 5–6 秒偶发错位闪屏。LED0 是正常心跳，LED1–3 稳定。
3. LED4–7 诊断位流使画面严重重复、错位，四个诊断灯仍全暗。该位流不适合继续使用。随后从厂商源文件重新生成恢复版，画面回到大部分稳定。
4. 共用输入像素时钟的对照位流使闪屏更快，因此“输入/输出像素时钟频差”不能单独解释故障。输出 PLL 路线保留在成功版本中。
5. 用户指出恢复版画面底边有电脑原画没有的短黑色缺口。检查 [`rd_buf.v`](../../fpga/project/stage2_ddr3_720p60_last_line/source/rtl/rd_buf.v) 的生成修改：VS 先预取第 1 行，随后有效区第 1～719 行应预取第 2～720 行；原条件 `wr_line != V_NUM` 提前停止，只发出 719 次读行请求。新版本仅将条件改为 `wr_line <= V_NUM`，合计预取 720 行。用户上板反馈问题解决。

末行漏读是源码中可直接确认的错误；它与本轮上板结果吻合。至少 30 分钟连续运行未复现此前的整屏错位，当前将其作为已解决问题归档。

## 2026-10-20：双帧池复制链路显示读故障修复结果

目标链路为 HDMI 输入 → 输入三槽帧池 → 原样帧复制 → 输出三槽帧池 → HDMI 输出。先前 `stage3_dual_pool_copy_recovery` 移除了显示适配器累计错误计数对输出的永久门控，并改成连续预取；其位流 SHA-256 `88CA1504B104AAA9A3557FED42D1E4BDBB6904CC1CB1C20C0D11B27BF021A6E9` 上板后画面比之前更严重，只有画面顶部有图像，LED 状态未变。此预取版失败，不能作为验收版本。

复查定位到消费指针 CDC 缺陷：读缓冲的二进制消费计数器经组合 XOR 转 Gray 后直接跨入 DDR 域。计数器进位时各位传播延迟不同，可能在同步器采样时得到错误指针，令适配器误判缓冲距离超限，即使缓冲中仍有未读数据也会阻断当前帧。定向仿真在实际已消费 512、返回写计数 992 时复现：旧逻辑错误采到消费值 0，计算占用 992、预留 16 beat，于真实尚有 480 beat 可读时触发错误。故 LED4 表示缓冲距离异常，不能单独作为 DDR 真实欠读的证据。

修复工程 `fpga/project/stage3_dual_pool_copy_cdc_fix` 在像素时钟域先寄存 Gray 指针，再用原有 DDR 域两级同步器接收。源码相对上一恢复工程的功能改动仅在 `rd_buf.v`；工程生成脚本亦已同步。仿真中在计数器低位/高位人为加入 0.1 ns / 2.1 ns 更新差时，旧版复现错误阻断；修复版在正常和延迟差模型下都完成两帧各 720 行，核对 230,400 个返回 beat 和 14,400 个 DDR 突发地址。PDS 全流程成功，所有受约束路径满足，DDR 慢角建立余量 +0.798 ns。布线后网表核对确认 10 位 Gray 源端寄存器直接进入 DDR 第一级触发器，后接第二级同步器；最大源端 CK-Q 加第一级输入路由延迟为 0.855 ns。

最新位流：`fpga/project/stage3_dual_pool_copy_cdc_fix/generate_bitstream/HDMI_IN_DDR3_HDMI_OUT_top.sbit`，SHA-256 `F332443546E9CDA0E2EE2CF346D7FC71988B35B42642E664718070BB33B884FB`。用户烧录此版后反馈 LED4、LED5 熄灭，其余灯正常；屏幕画面正常显示。按本版映射，LED4 为显示适配器累计缓冲错误、LED5 为读仲裁器错误、LED6 为当前显示输出门控、LED7 为曾输出非零 RGB。实板已首次恢复正常，但尚无此版运动画面连续 30 分钟稳定运行记录，暂不标记为长期验收完成。
