# Stage 8 Brown 畸变矫正效果评估

日期：2026-10-26  
评估对象：`fpga/project/stage8_brown_y_mul_fix_test`  
依据：紫光同创《2026 FPGA 创新设计赛道选题指南》选题二，PDF 打印页 10–11（功能精度、标定参数、网格直线度/MTF50/SFR、处理延迟/帧率、资源、时序和真实参数要求）。

评估基准为已提交的 `ffa0595`（修复 RTL 和已通过 PDS 的位流）。评估过程中工作区又出现未提交的调试探针改动：`fram_buf.v`、构建脚本和 FIC 均已变化。当前 `.sbit` SHA-256 仍为 `DEDD34AA…EDA8A31`，但工作区 `.fic` 已变为 SHA-256 `74E38632…997228C`，与对应综合 FIC 的 `3F9B42B9…E2B7C6C` 不同。**当前目录下这个 sbit 与修改后的 fic 不匹配，不能作为配套烧录文件**；需按新的探针配置重新跑 PDS，或恢复与旧 sbit 匹配的 FIC。以下布局时序和资源数值对应已提交构建，不代表这些未提交修改的构建结果。

## 结论

当前工程已把此前导致画面下半部黑屏的 Brown 负 Y 校正路径错误修正，并通过定向 RTL 仿真和 PDS 布局布线时序检查；但**尚不能判定矫正效果达到赛题的高精度要求**。主要原因是本镜头标定出的 `k3` 被 FPGA 忽略，依据当前标定图计算，去掉 `k3` 后的整幅逆向采样映射与完整 OpenCV 五系数映射相差 **P95 12.11 px、最大 36.93 px**。这不是实板残差的直接测量值，却说明现有四系数实现对这颗镜头存在显著模型截断风险。

另外，新位流尚无烧录后的矫正图；标准网格直线度、斜边 MTF50/SFR、实际帧率和端到端延迟都没有测量。因此当前状态适合称为“坐标乘法故障修复候选版”，不能称为“矫正效果验收通过”。指南没有提供量化评分权重，本报告不虚构总分。

## 已有数据与可支持的判断

### 标定参数

`host/calibration/output/calibration.json` 对应 DCXGW10 相机、1280×720 模式和 9×6 内角点、25 mm 方格。数据包含 33 张完整棋盘格视图、10 张通过验证的部分棋盘格视图，另有 18 张未通过检测的图像。完整 33 视图基线 RMS 为 0.4708 px，43 个接受视图的全局拟合 RMS 为 0.5165 px。

相机矩阵和畸变参数为：

| 参数 | 标定值 |
|---|---:|
| `fx`, `fy` | 850.1754 px, 853.8549 px |
| `cx`, `cy` | 603.2727 px, 353.8631 px |
| `k1`, `k2` | -0.4147729, +0.2415033 |
| `p1`, `p2` | +0.00132371, +0.00009912 |
| `k3` | -0.08895112 |

这些数据满足“基于真实相机标定”的方向要求。重投影 RMS 反映棋盘角点拟合误差，**不等同于矫正后直线度误差**，也不能替代 MTF50/SFR。

### 当前 FPGA 模型与光学模型差异

当前 `fractional_brown_mapper.sv` 使用 `k1/k2/p1/p2`，没有 `k3` 项。标定程序已计算完整模型与置零 `k3` 模型的逆向坐标图差异：P95 为 12.1124 px，最大值为 36.9294 px。该差异集中在全视场的较大半径区域，会使边缘直线残留弯曲或位置偏差；确切视觉表现仍需用标准网格实测。

该量化结果也超过 `host/calibration/export_fixed_parameters.py` 中默认的 0.5 px 导出门限。换言之，现有导出工具本会拒绝生成四系数近似参数；测试工程里直接使用四系数常量并没有通过这一近似误差门槛。建议先接入 `k3`，再按硬件实际定点算法导出并逐像素对照软件参考。

### 黑屏故障修复与硬件实现

旧位流的 Fabric Debugger 数据显示：对同一像素，`total_y8=-406` 时数学期望的 Q16.16 校正值为 `0xFFFAB5D6`，旧实现测到 `0x017AB5D6`，多出 `0x01800000`（+384 px）；相邻像素也有相同偏差。这会把源 Y 坐标推到有效范围外，因而规划器将样本输出为黑色。

新工程将取绝对值、无符号乘法、恢复符号拆到流水级。目标像素定向仿真、Stage 8 坐标链、60 组参考向量、回压和严格边界检查通过。PDS 报告 `All Constraints Met`；125 MHz `ddrphy_sysclk` setup WNS +0.132 ns、hold WHS +0.100 ns，失败端点均为 0。该 setup 裕量仅 132 ps，虽然满足当前报告约束，仍应留意工具版本、增量改动和板上运行稳定性。

这些结果证明修复候选版可综合且时序通过，**不证明修复版已在开发板上消除黑区**。已有黑屏照片和旧 Listing 属于旧位流，不能作为新位流的效果结果。

## 建议的验收实验

1. **补齐 `k3` 并冻结参考模型。** 把实际标定五系数和 intrinsics 作为唯一参数来源；在固定映射方向、定点舍入和有效边界后，对整幅 1280×720 坐标图做 bit-accurate 对比，报告误差 P50/P95/max 和有效像素比例。不能仅用 60 个离散点代表全视场精度。
2. **同场景拍摄原始/矫正标准网格。** 用覆盖四边和四角的平面网格或棋盘格，固定相机、焦点、曝光和画面范围；对网格线分段拟合直线，分别报告中心/中场/四边/四角的平均、P95、最大正交距离误差（px），同时报告黑边面积比例和断裂线段数。按物理角度至少测正视和若干倾斜角度。
3. **测重采样清晰度。** 拍摄指南建议的倾斜黑白边或标准 slanted-edge 图卡，对原图和矫正图在中心、边缘相同 ROI 计算 MTF50/SFR；记录像素尺寸、缩放/裁剪、插值方式和测量软件版本。几何变直与清晰度变化分开报告。
4. **验证新位流和运行指标。** 配套烧录本工程 `generate_bitstream/` 内的 sbit/fic，先确认 `0x8F076` 附近 `correction_y10` 负号正确、`mapped_y11` 在范围内且 `plan_geometry_valid` 合理；再检查整帧四边。以至少 10 秒稳定输入计算输入/输出 fps、丢帧/覆盖数和端到端延迟。当前帧周期计数只有 24 位，在 125 MHz 下约 0.134 s 即饱和，测量前应扩展计数器或用长窗口累计事件。
5. **记录可复现的工程资源。** 将修复版的 LUT、寄存器、DSP、DRM/eRAM 使用量与时序报告、PDS 版本、位流/FIC 哈希一并归档；若启用动态角度，再单独测该路径的最坏时序及帧边界切换行为。

## 评估结论

Stage 8 已完成一个关键坐标乘法故障的工程修复候选，并具备真实相机标定基础；但当前四系数模型与五系数标定的全视场映射差异过大，且修复版尚无板上图像质量和实时性能测量。建议先实现 `k3`，再进行同条件网格与斜边测试。完成这些实验前，项目状态定为：**坐标故障修复待实板复核，光学矫正精度待提升和验收，实时性能待测。**
