# 1080P30 畸变矫正吞吐架构设计

## 1. 目标

将 MES50HP / PGL50H 视频链路的正式运行模式定义为：

```text
HDMI RX 1920×1080@30 fps
    → DDR3 输入帧缓存
    → Brown-Conrady 畸变矫正与双线性插值
    → DDR3 输出帧缓存
    → HDMI TX 1920×1080@30 fps
```

系统在没有板卡时，必须通过完整光栅仿真、DDR 行为模型和 PDS 器件级综合证明算法吞吐设计；真实 DDR3 有效带宽、HDMI 收发和长期稳定性仍由实板验收。

## 2. 性能边界

| 项目 | 数值 |
|---|---:|
| 输出分辨率 | 1920×1080 |
| 输出帧率 | 30 fps |
| 每帧有效像素 | 2,073,600 |
| 有效像素吞吐 | 62.208 Mpixel/s |
| HDMI 像素时钟 | 74.25 MHz |
| 算法/DDR 用户逻辑目标时钟 | 100 MHz |
| 每帧 100 MHz 周期预算 | 3,333,333 |
| 平均周期预算 | 1.607 cycles/pixel |
| DDR3 理论峰值 | 3.2 GB/s |

当前逻辑像素读取路径会对一个双线性输出像素串行读取四个 RGB888 源像素。每次源像素请求又消耗一个 256-bit DDR 返回拍，等效源读取为 128 Byte/output pixel，即 7.96 GB/s，仅输入采样已经超过 DDR3 理论峰值。因此该路径仅保留为功能验证参考，不得用于 1080P30 实时模式。

## 3. 已冻结的架构决策

### 3.1 帧存储格式

算法输入帧和算法输出帧统一采用 `RGBX8888`：

```text
bit [31:24] = 8'h00
bit [23:16] = R
bit [15:8]  = G
bit [7:0]   = B
```

每个 256-bit DDR 数据拍恰好容纳 8 个连续像素。HDMI 输入侧在写入 DDR3 时完成 RGB888 到 RGBX8888 的扩展；HDMI 输出侧在读取 DDR3 后丢弃高 8 bit。禁止在实时处理帧中采用紧凑 RGB888 字节寻址。

一帧 RGBX8888 图像为 8,294,400 Byte。输入写、源图缓存读取、输出写和显示读四个连续帧流合计约 995 MB/s；缓存填充与读写仲裁带来的额外量按总有效流量不超过 1.2 GB/s 进行设计预算。

### 3.2 缓存单元

源图 Local Pixel Cache 使用以下固定首版参数：

| 参数 | 值 |
|---|---:|
| Tile 宽度 | 32 pixel |
| Tile 高度 | 4 line |
| 像素位宽 | 32 bit |
| 单 Tile 数据量 | 512 Byte |
| 驻留 Tile 数 | 128 |
| 组织 | 16 set × 8 way，偏斜组索引 |
| 数据区容量 | 64 KiB |
| 替换策略 | 每组伪 LRU |

线性帧布局下，一个 Tile 的四行不是连续地址。每个 Tile Fill 固定发起四个读取命令，每行读取 4 个连续 256-bit 数据拍；总共读入 16 拍、512 Byte。组索引使用 `tile_x - tile_y + (tile_x >> 2)` 的低位结果，降低畸变映射造成的纵向 Tile 冲突。首版采用阻塞式 Miss：Tile 未命中时暂停执行队列头部坐标，完成四行填充后继续。首版不允许将四个相邻像素拆为四次 DDR 单像素访问。

### 3.3 同周期双线性邻域读取

缓存数据按 `{source_y[0], source_x[0]}` 分入四个独立 RAM 银行。任意连续 2×2 邻域的 `P00/P10/P01/P11` 分别位于四个不同银行，因此命中时能够在一个算法时钟周期内读出四个 RGBX8888 像素。

命中路径为：Tag 查询、四银行读取、RGB 取低24 bit、现有 `bilinear_interp`。该路径的接口采用 `valid/ready`，其吞吐目标为连续一像素每周期。Tile 边界处最多查询四个 Tile Tag；只要四个 Tag 均有效，仍按同一周期交付邻域。

### 3.4 坐标与缓存解耦

现有 `distortion_image_pipeline` 只允许一个坐标在途，不能用于实时模式。新路径将把坐标生成和像素获取拆开：

```text
坐标扫描器/畸变流水线
    → 坐标 FIFO（深度 512）
    → Tile Tag 查询与 Miss 控制
    → 四银行邻域读取
    → 双线性插值
```

FIFO 条目包含 `x0`、`y0`、`fx`、`fy`、`coord_valid`、`sof` 和 `eol`。无效坐标不访问缓存，直接向插值输出路径提供黑色像素，并保留帧/行标志。缓存 Miss 只阻塞 FIFO 出队，坐标生成应在 FIFO 未满时持续运行。

### 3.5 DDR 调度与帧缓冲

帧缓冲使用输入/输出各两块区域，以 Ping-Pong 方式避免读写覆盖：

```text
输入帧 A/B：HDMI RX 写入当前帧，算法读取上一完整帧
输出帧 C/D：算法写入当前结果，HDMI TX 显示上一完整结果帧
```

DDR 仲裁优先级固定为：

1. HDMI 输出行预取，避免显示下溢；
2. HDMI 输入写入，避免接收丢帧；
3. Tile Cache Fill；
4. 算法输出帧写入。

输入写、输出写和显示读维持长连续突发。Tile Fill 使用每行 4 拍突发。DDR 用户接口在不支持读取命令重叠时，首版仍以完整 4 拍突发消除单像素命令开销；若性能测试显示 Miss 等待超过预算，再加入两个在途 Tile Fill 请求。

### 3.6 视频时序

输出视频时序从当前固定 1280×720 配置扩展为参数化模式，正式模式采用 CEA-861 1920×1080@30：74.25 MHz 像素时钟、2200 总像素/行、1125 总行/帧。HDMI RX PCLK、DDR 用户时钟、算法时钟和 HDMI TX PCLK 不假设同频或同相；跨域控制只通过双触发同步、异步 FIFO 或现有官方双口帧缓存逻辑传递。

## 4. 组件边界

| 组件 | 职责 | 不负责 |
|---|---|---|
| `coordinate_fifo` | 缓存坐标及帧标记，提供 `valid/ready` 解耦 | DDR 命令与缓存替换 |
| `ddr_burst_reader` | 执行每行 4 拍的 DDR 读取事务，返回连续 256-bit拍 | Tag 查询与像素选取 |
| `pixel_tile_cache` | Tag、伪LRU、四银行数据存储、Tile Fill 写入、2×2命中读取 | 畸变坐标计算和DDR协议细节 |
| `cached_pixel_fetch_engine` | 将 FIFO 坐标转换为Tile查询、处理Miss、产生4邻域或黑色邻域 | 双线性数学运算 |
| `mes50hp_top` | 扫描、帧控制、模块连接、完整帧完成统计 | 直接产生DDR单像素地址 |
| `pgl50h_board_top` | HDMI/DDR IP、Ping-Pong地址、CDC、显示时序与板级控制 | 算法缓存内部实现 |

现有 `pixel_fetch_engine.sv`、`ddr3_pixel_read_adapter.sv` 和 `distortion_image_pipeline.sv` 保留给小图与回归测试；1080P30 数据路径不再通过它们逐像素读取。

## 5. 验收条件

无板卡阶段应同时满足：

1. 完整 1920×1080 坐标光栅下，所有有效与无效坐标均符合 Python 定点黄金模型。
2. DDR 行为模型包含非零延迟、命令背压、数据背压和读写仲裁；结果图与黄金图逐像素一致。
3. 在 100 MHz 算法时钟下，一帧处理周期不超过 3,333,333；平均不超过 1.607 cycles/pixel。
4. 当前 identity、barrel、pincushion 三组相机参数下，Tile Cache 源读取量不超过 10 MB/frame，且源读取平均突发长度固定为 4 个 256-bit 拍。
5. 坐标 FIFO、Tile Fill 队列、输入帧缓冲、输出帧缓冲均无上溢、下溢、重复像素或丢失像素。
6. PDS 对 `PGL50H-6IFBG484` 的综合、布局布线和静态时序报告中，100 MHz算法时钟满足约束；HDMI/DDR3真实物理时序仅在官方IP和约束导入后检查。

## 6. 方案取舍

| 方案 | 结论 | 原因 |
|---|---|---|
| 四次单像素随机读取 | 拒绝 | 仅源读取已达7.96 GB/s，超过3.2 GB/s理论峰值 |
| 4×2单Tile缓存 | 拒绝 | 容量太小且稀疏抽样模型不能代表完整1080P光栅局部性 |
| 32×4、128 Tile、16组×8路偏斜索引、阻塞Miss | 首版采用 | 64 KiB片上数据量可控，完整光栅模型下畸变源读取低于10 MB/frame，DDR读取以4拍突发进行 |
| 预取与多在途Tile Fill | 条件采用 | 仅在阻塞Miss超过100 MHz帧周期预算后加入 |
| 1080P60 | 本阶段不采用 | 需要148.5 MHz像素时钟与124.416 Mpixel/s算法吞吐 |

## 7. 风险与处理

| 风险 | 处理方式 |
|---|---|
| 实际标定参数导致Tile局部性变差 | 使用完整光栅缓存模型将真实标定参数纳入每次回归；超过10 MB/frame时先扩大Tile数量或增加预取深度 |
| PDS推断的DRM数量高于预算 | 首先保持Tile尺寸不变，降低驻留Tile数至96并重跑完整光栅模型；禁止退回单像素DDR访问 |
| 阻塞Miss导致帧周期超限 | 增加Tile Fill请求队列和两个在途读取；不改变像素计算精度 |
| DDR读写仲裁造成HDMI下溢 | 显示预取最高优先级，输入写次高优先级，并在仿真中显式检查下溢标志 |
| 1080P30显示时序与当前720P模块不兼容 | 将时序参数化并单独验证同步、DE有效区和帧边界，不复用固定720P常量 |

## 8. 非目标

- 本阶段不承诺1080P60。
- 本阶段不使用摄像头专用ISP、自动标定或运行时动态标定参数更新。
- 本阶段不把真实DDR3 PHY校准、HDMI芯片I2C配置成功或板卡长期稳定性当作无板仿真结论。
