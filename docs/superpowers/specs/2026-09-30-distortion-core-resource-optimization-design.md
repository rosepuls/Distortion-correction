# 畸变核心资源优化设计

## 背景与问题

`distortion_core.sv` 的基准实现为保留 Python 任意精度中间结果，使用了最高 228 bit 的乘法路径。PDS 2022.2-SP6.4 对 PGL50H 的独立综合结果为 17,292 LUT、2,096 FF 和 84/84 APM；该资源占用不能与双线性插值、预处理和系统控制逻辑共同部署。

本优化只改变内部数学实现，不改变现有模块端口、无反压 `valid/sof/eol` 语义、SOF 配置锁存规则，或每拍接受一个有效坐标的吞吐目标。

## 目标与验收门限

| 项目 | 基准实现 | 优化目标 |
|---|---:|---:|
| 吞吐 | 1 coordinate/clock | 保持 1 coordinate/clock |
| 核心延迟 | 5 clocks | 允许增加，固定且记录 |
| APM | 84 | 不高于 40 |
| 坐标最大误差 | 基准 | 相对基准模型不高于 1/16 pixel |
| 坐标平均误差 | 基准 | 相对基准模型不高于 1/64 pixel |
| 边界决策 | 基准 | `coord_valid` 必须一致 |

误差在有效、非边界坐标上计算；任何导致 `coord_valid` 与基准不一致的向量均视为失败，不能以平均误差抵消。

## 优化架构

### 1. 参数化范围扫描与黄金模型

`software/bitaccurate_distortion.py` 增加可配置内部格式和扫描报告：针对 1280×720 及配置的相机参数，统计 `x/y`、`r2`、径向项、切向项和源坐标的最小/最大值；同一批坐标分别走基准格式与候选格式，输出最大、平均和 RMSE 坐标误差，以及 `coord_valid` 差异数。

候选格式的每一次截断必须在 Python 中先实现并通过误差门限，才能迁移到 RTL。溢出采用显式饱和或按已证明范围保留足够整数位；禁止依赖 Verilog 隐式截断。

### 2. Horner 径向多项式

基准径向项：

```text
radial = 1 + k1*r2 + k2*r4
```

优化后采用：

```text
t      = k1 + k2*r2
radial = 1 + r2*t
```

在同一候选 Q 格式定义下，两者以 Python 黄金模型校验。Horner 形式避免显式保留 `r4` 的 Q8.112 宽乘积，并减少一条宽乘法链。

### 3. 分级截断与乘法宽度

优化版在每个数学阶段寄存前量化到已验证格式：归一化坐标、平方/交叉项、`r2`、Horner 中间项、径向/切向项和反归一化坐标。每个候选格式同时定义有符号总位宽与小数位；具体值不在此规格预设，而由范围扫描的最小满足误差格式确定。总位宽是 APM 推断约束的一部分，RTL 不得只缩减乘积输出而保留宽输入操作数。

优先策略是降低乘法器输入宽度，而非仅截断乘积输出；PDS APM 推断取决于两个操作数的实际位宽。保留与基准一致的算术右移方向和 Q13.19 输出格式。

### 4. RTL 与验证

实现新增参数化优化路径，基准路径保留为对照，默认由单一参数选择，避免改变端口。Testbench 对黄金向量逐项比较：源坐标误差、整数 floor、Q0.16 小数、`coord_valid` 和控制信号。连续两帧、空拍、复位和边界回归必须在优化路径重新执行。

每轮候选格式执行：Python 范围/误差报告、XSim 回归、PDS `Compile → Synthesize`。仅在 APM 与误差均满足目标时，才更新默认路径；独立 `distortion_core` 顶层因 579 IO 不执行 Device Map，PDS 资源记录止于综合。

## 非目标

- 不添加假时钟、假引脚或改动 `distortion_core` 公共端口。
- 不实现 DDR Pixel Fetch、Cache、HDMI 或系统顶层。
- 不以降低每拍吞吐为代价做单乘法器多周期复用。
- 不在缺少相机参数范围依据时随意删除整数位。
