# PGL50H 连续帧视频流设计

## 目标

将 PGL50H 顶层从单次“采集一帧 → 处理一帧 → 循环显示”改为 1280×720@30 的连续帧视频流。每个完整 HDMI 输入帧都进入畸变校正路径；端到端允许帧级延迟，不要求逐行低延迟。

## 范围与不变量

- 保留 100 MHz `ddrphy_clkin`、现有 Tile Cache、畸变数学和 720p30 图像 golden。
- 输入帧必须完整写入 DDR 后才能被畸变校正随机读取。
- HDMI 输出只能在垂直帧边界切换完整输出帧，禁止读写同一输出帧。
- 任何输入帧到达时算法仍在处理上一帧，必须报告过载；不得静默复用或覆盖被处理的输入帧。

## 帧存储布局

输入使用 DDR 区域 A/B：采集器写 A 时算法仅读 B，下一帧交换。输出使用独立区域 C/D：算法写后备区，HDMI 连续读取前景区。四个区域各为一帧，720p RGBX 输入每区 3,686,400 byte；RGB888 输出区域沿用现有逐行打包格式。

## 数据流

```text
HDMI RX ──连续写入 A/B──> 完整帧事件 ──> 算法随机读 A/B
                                              │
                                              └──连续写入 C/D
                                                          │
HDMI TX <──帧边界原子切换 C/D <── 输出帧完成事件 ────────┘
```

## 控制与 CDC

`realtime_frame_scheduler` 位于核心时钟域，接收输入帧完成事件和算法/输出写完成事件。它只在算法空闲时对已完成输入帧产生一个 `process_start`，锁存输入帧基址及与当前显示 bank 相反的输出 bank。完成的输出 bank 通过 toggle + 两级同步器传到视频像素域；像素域仅在下一次输出帧开始时采用新 bank。

采集持续使能。输出 bank 的选择在处理开始时锁存，输出写入器对一帧的所有行使用同一锁存基址。显示读出器在帧开始时锁存当前 bank，保证整帧地址一致。

## DDR 仲裁

写方向在“HDMI 输入帧写入”和“算法输出帧写入”之间按事务锁定仲裁；读方向在“HDMI 显示预取”和“Tile Cache fill”之间按事务锁定仲裁。一次命令获准后，其数据拍、backpressure 和完成信号只能返回给原请求者。显示预取优先于 Cache fill，以防输出下溢；输入/输出写采用轮转优先级，避免其中一方长期饥饿。

## 验证

1. 单元 XSim：调度器连续接收三帧完成事件时，依次启动三次处理并交替输入/输出 bank；算法忙时必须置过载而不是覆盖所有权。
2. 单元 XSim：两个读/写客户端的事务锁定仲裁在 backpressure 下不串接数据或完成事件。
3. 集成 XSim：板顶层可编译；连续帧结构测试检查 bank 交换、帧边界显示切换和无撕裂地址选择。
4. 整图 XSim：覆盖 `result/sim_assets/cache_full_chain_1280x720/`，保持 921,600 像素逐像素匹配以及既有 720p30 吞吐门槛。

## 非目标

本次不把畸变校正改为逐行算法，也不更改 DDR3 IP、HDMI IP、像素格式、相机标定寄存器接口或时钟频率。
