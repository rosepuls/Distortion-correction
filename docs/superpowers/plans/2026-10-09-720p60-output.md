# 720p60 HDMI Output Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Change the PGL50H HDMI transmitter to standard 1280×720 progressive 60 Hz while the capture and distortion pipeline remain 1280×720 at 30 fps, displaying each completed result for two output refreshes under normal load.

**Architecture:** Keep the existing 1650×750 raster and double only the transmitter pixel clock from approximately 37.125 MHz to 74.25 MHz. The output-frame bank remains selected by the completed-frame toggle; when no new result has completed, the display reader rereads the active bank. Move the bank selection boundary to the start of VS, because the DDR frame reader captures its base address there.

**Tech Stack:** SystemVerilog RTL, Vivado XSim testbenches, Pango PDS 2022.2 PLL/IP and FDC constraints, MES50HP/PGL50H HDMI/DDR3 board integration.

## Global Constraints

- Keep input `pixclk_in` constrained at 37.125 MHz and retain the 30 fps capture/algorithm budget.
- Use 1280×720 with `H_TOTAL=1650`, `H_SYNC=40`, `H_BACK=220`, `H_FRONT=110`, `V_TOTAL=750`, `V_SYNC=5`, `V_BACK=20`, `V_FRONT=5`; use positive HS/VS polarity.
- Do not change the distortion arithmetic, DDR frame layout, RGB888 output packing, or HDMI I²C initialization in this feature.
- The only intentionally tolerated timing issue is the already-recorded DDR PHY micro-hold violation; no new `video_pixel_clk` setup, hold, recovery, or removal violation is acceptable.
- Preserve the `cfg_clk` to `video_pixel_clk` reset-CDC false path and its audit script.


