# Stage 9 Catmull–Rom 窗口复用优化计划

## 目标

从 `stage9_bicubic_catmull_rom_brown_fix_test` 派生独立的 `stage9_bicubic_catmull_rom_window_reuse_test`，降低 4×4 邻域读取器在连续水平扫描中的 cache 查询次数，并保留 Brown 修复版、Catmull–Rom 输出和 DDR 通路供实板对照。

## 方案

读取器保留最近一次完成的 4×4 样本窗口及整数源坐标起点。若下一请求有效、横向起点恰好增加 1 且纵向起点不变，则把旧窗口左移一列，只查询新窗口最右侧一列所需的两个 2×2 邻域；其他坐标关系按原路径执行四次查询。无效边界请求和新的源帧开始会使窗口失效。缓存请求、输出样本顺序、元数据、反压、插值算术和现有 DDR 接口不变。

## 验收

1. 读者级仿真比较同一缓存命中窗口的完整读取与连续水平读取，断言输出像素一致且 cache 查询由 4 次降至 2 次。
2. 仿真覆盖坐标跳变回退、行坐标变化回退、黑边请求、输出反压和源帧失效。
3. 运行 Stage 9 1280×720 全帧仿真，检查像素、地址、帧完成和排空行为。
4. 完整 PDS 构建，核对 `.sbit/.fic` 同次构建哈希及布线后时序；不以仿真或构建结果推断实板帧率。
5. 更新工程 README 和结果记录，明确需要用新工程对应的 `.sbit/.fic` 实板测量，并与 Brown 修复基线在相同输入下比较。

## 范围

不改动 Brown 映射、Catmull–Rom 插值公式、Stage 8/原 Stage 9/Brown 修复基线、参数协议、DDR 仲裁策略或缓存容量。若坐标映射导致较少的水平连续命中，先通过新增窗口复用计数和实板周期统计判断收益，再决定是否扩展到垂直或对角复用。
