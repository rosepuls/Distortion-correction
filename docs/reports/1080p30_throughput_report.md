# 1080P30 吞吐基线报告

## 测试对象

- 分辨率：1920×1080
- 光栅顺序：逐行、逐像素
- 算法时钟模型：100 MHz
- 单帧周期预算：3,333,333 cycles
- 源帧格式：RGBX8888
- Tile：32×4 pixel，16 set × 8 way
- DDR 数据拍：256 bit，Tile 行突发长度 4 beats

## RTL 基线结果

| 指标 | 结果 |
|---|---:|
| 输入像素数 | 2,073,600 |
| 输出像素数 | 2,073,600 |
| 帧处理周期 | 2,567,797 |
| 平均 cycles/pixel | 1.238328 |
| DDR 行命令数 | 68,016 |
| 帧预算 | 3,333,333 |
| 预算余量 | 765,536 cycles |

## 结论

在命令可立即接收、数据拍连续返回的 DDR 基线模型下，连续命中路径已经达到一拍一个坐标的吞吐，完整 1080P30 光栅处理周期满足预算。此前单坐标串行版本为 4.134766 cycles/pixel，已由命中路径流水化修正。

本结果尚不等价于板上最终验收：下一阶段必须加入 DDR 命令背压、可变读延迟、数据背压以及输入写/输出写/显示读竞争，重新测量帧周期和 FIFO 水位。

## DDR 压力结果

压力模型采用周期性命令背压，以及每条 Tile 行命令首拍 3–11 个时钟的可变等待；四拍 burst 内部连续返回，数据有效保持到接收端握手。结果如下：

| 指标 | 压力结果 |
|---|---:|
| 输入/输出像素数 | 2,073,600 / 2,073,600 |
| 帧处理周期 | 3,032,897 |
| 平均 cycles/pixel | 1.462624 |
| DDR 行命令数 | 68,016 |
| 预算余量 | 300,436 cycles |

该结果覆盖了当前阻塞式 Tile Fill 的首版延迟边界。若真实 DDR 仲裁使突发内部出现更长的数据空洞，仍需在板级 DDR 行为模型中重新测量，并再考虑 Tile Fill 预取或多在途读。
