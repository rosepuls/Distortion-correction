# 图像边界与异常输入处理规范

## 1. 目的

本文档规定 3×3 邻域、畸变坐标和双线性插值在图像边界处的确定行为。Python Float Model、Bit-accurate Model、RTL 和 Testbench 必须使用相同规则。

如果后续修改边界策略，必须同时更新四类实现，不能只修改其中一处。

---

## 2. 图像坐标定义

对于宽度 `W`、高度 `H` 的图像，有效整数像素坐标为：

```text
0 ≤ x ≤ W-1
0 ≤ y ≤ H-1
```

左上角为 `(0,0)`，右下角为 `(W-1,H-1)`。

线性逻辑像素地址为：

```text
addr = y × FRAME_STRIDE_PIXELS + x
```

当图像紧密排列时：

```text
FRAME_STRIDE_PIXELS = W
```

---

## 3. 3×3 邻域边界

第一版采用零填充：

```text
访问坐标在图像内  → 使用真实像素
访问坐标在图像外  → 使用 0
```

因此对于中心坐标 `(x,y)`，窗口元素定义为：

```text
window[j][i] = image[y+j-1][x+i-1]
```

若右侧坐标不满足有效范围，则对应 `window[j][i]=0`。

输出图像仍保持 `W×H`，不裁掉边缘。Gaussian、Sobel、Erosion 和 Dilation 共用这一窗口边界定义。

### 3.1 二值形态学

二值图像的图像外区域视为背景：

```text
outside binary pixel = 0
```

这意味着边缘处的 Erosion 更容易得到 0，Dilation 不会从图像外引入前景。

### 3.2 流式实现要求

流式 Window Generator 可以延迟输出，但逻辑输出坐标必须仍与窗口中心对应：

```text
out_pixel(x,y) 对应以 input_pixel(x,y) 为中心的 3×3 窗口
```

不能为了简化移位寄存器而把输出悄悄对齐到窗口右下角。硬件需要的行延迟和列延迟必须通过控制信号同步补偿。

---

## 4. 畸变源坐标边界

畸变坐标输出为定点源坐标：

```text
src_x = x0 + dx
src_y = y0 + dy
```

其中：

```text
x0 = floor(src_x)
y0 = floor(src_y)
0 ≤ dx < 1
0 ≤ dy < 1
```

第一版 Bilinear 只有在四个采样点全部位于图像内部时才有效：

```text
0 ≤ x0 < W-1
0 ≤ y0 < H-1
```

等价于：

```text
P00 = image[y0    ][x0    ]
P10 = image[y0    ][x0 + 1]
P01 = image[y0 + 1][x0    ]
P11 = image[y0 + 1][x0 + 1]
```

四个像素全部有效时：

```text
coord_valid = 1
```

否则：

```text
coord_valid = 0
output_pixel = 0
```

因此，源坐标即使恰好落在最后一列或最后一行，也因为缺少 `x0+1` 或 `y0+1` 邻点而输出黑色。第一版不做坐标 Clamp，也不对缺失邻点做部分插值。

这一规则实现简单且确定，但会使矫正图像最外侧产生最多一像素的黑边。后续如需改善，可以增加 Clamp 或零边界参与插值模式，并作为新的明确配置，而不是修改现有模式含义。

---

## 5. 双线性输出边界

当 `coord_valid=1` 时：

1. 按 `numeric_spec.md` 的位宽计算；
2. 按规定位置缩放；
3. 将结果饱和到 8 bit。

```text
result < 0     → 0
result > 255   → 255
otherwise      → result
```

当 `coord_valid=0` 时，不发起 Pixel Fetch 请求，RGB 三通道直接输出 0。

---

## 6. `valid`、空拍与帧边界

### 6.1 输入空拍

当 `in_valid=0`：

- 不接收 `in_pixel`；
- x/y 有效像素坐标不更新；
- 3×3 窗口不移入无效数据；
- `in_sof/in_eol` 被忽略；
- 模块仍可输出此前流水中的有效结果。

### 6.2 行尾

当 `in_valid=1 && in_eol=1`：

- 当前像素是本行最后一个有效像素；
- 下一有效输入像素属于下一行；
- 水平移位窗口不得把上一行末尾像素带入下一行开头；
- 行计数加一，列计数归零。

### 6.3 帧首

当 `in_valid=1 && in_sof=1`：

- 当前像素坐标强制视为 `(0,0)`；
- 新一帧的行列计数重新开始；
- 不允许上一帧窗口数据参与新一帧计算；
- 帧配置参数在此时锁存。

### 6.4 连续两帧

Testbench 必须覆盖连续两帧，且两帧内容明显不同，以检查：

- 行缓存残留；
- 流水有效位残留；
- `sof/eol` 错位；
- 上一帧最后一行污染下一帧第一行。

---

## 7. 复位处理

复位有效时：

```text
out_valid = 0
out_sof   = 0
out_eol   = 0
```

行缓存、窗口寄存器、坐标计数和有效流水必须进入已知状态。

解除复位后，在收到新的有效 `sof` 前不得产生被标记为一帧有效开头的数据。

Testbench 至少验证：

- 帧开始前复位；
- 一行中间复位；
- 一帧中间复位；
- 复位解除后重新从 `sof` 开始。

---

## 8. Python 与 OpenCV 对齐

OpenCV 参考调用必须显式指定：

```text
interpolation = INTER_LINEAR
borderMode    = BORDER_CONSTANT
borderValue   = 0
```

但 OpenCV 在最外层像素处可能使用“部分邻点在图像外并以 0 参与插值”的行为，而第一版 RTL 采用“四邻点不完整则整像素输出 0”。

因此比较时分为两类区域：

```text
内部有效区域：要求按模型误差阈值比较
四邻点不完整区域：按本项目规则比较，不直接要求等于 OpenCV
```

Python 项目模型必须显式实现本文件规则，不能完全依赖 OpenCV 默认行为。

## 9. 必测边界用例

### 9.1 3×3 窗口

- [ ] `(0,0)`；
- [ ] `(W-1,0)`；
- [ ] `(0,H-1)`；
- [ ] `(W-1,H-1)`；
- [ ] 第一行中间；
- [ ] 最后一行中间；
- [ ] 第一列中间；
- [ ] 最后一列中间；
- [ ] 内部普通像素。

### 9.2 Bilinear

- [ ] `src_x/src_y` 为 0；
- [ ] `dx/dy` 为 0；
- [ ] `dx/dy` 接近 1；
- [ ] 负源坐标；
- [ ] 最后一列；
- [ ] 最后一行；
- [ ] 四邻点全部有效的最大坐标；
- [ ] 四邻点至少一个无效；
- [ ] 输出需要下限饱和；
- [ ] 输出需要上限饱和。

### 9.3 流控制

- [ ] 连续有效输入；
- [ ] 行内插入空拍；
- [ ] 行尾前后插入空拍；
- [ ] 连续两帧；
- [ ] 帧中复位并重新同步。

## 10. 修改控制

任何边界策略变化都必须在提交说明中列出：

```text
旧规则
新规则
受影响的软件文件
受影响的 RTL 文件
需要重新生成的测试向量
OpenCV 对比区域是否变化
```

未经记录，不允许出现 Python、RTL 和 Testbench 使用不同边界策略的情况。
